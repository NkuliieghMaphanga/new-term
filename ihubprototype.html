Project Overview

The iHub Africa Prototype is a client website built to represent a real-world brand online. Unlike a personal practice project, this build had to reflect an existing organisation's identity and communicate its offering clearly to visitors who had never encountered iHub Africa before.

I focused on planning a clear information architecture first — deciding what pages and sections a visitor needed, and in what order — before styling anything. That structure was then built out into responsive, semantic HTML and CSS so the site would hold up across devices and be easy to extend later.

This project demonstrates my ability to work from a client's brand and goals, rather than a fixed design file, and turn that into a working prototype ready for feedback and iteration.

Problem Statement

iHub Africa needed a website that a first-time visitor could navigate confidently — understanding who the brand is, what it offers, and how to take the next step, without confusion. The objective was to design a clear site structure and a visual identity that felt professional and trustworthy, then implement it as a responsive front end.

The challenge was balancing a real client's brand expectations with clean, maintainable code, while keeping the site fast, accessible and consistent across devices.

Development Process

Development began with sketching the site's information architecture — mapping out what pages and sections a visitor to iHub Africa would need, and in what order they should appear. Only once that structure felt right did styling and brand identity work begin.

Sections were built as reusable HTML and CSS components, then refined against feedback to better match the client's expectations. Responsive layouts were implemented using CSS Flexbox and Grid, and JavaScript was layered in to support navigation and interactive elements.

Solutions Implemented

Content structure challenges were solved by mapping out a simple sitemap before writing code, so every section had a clear purpose. Brand consistency was maintained by defining reusable CSS custom properties for colour and type, keeping the whole site visually coherent.

Responsive design techniques such as CSS Grid, Flexbox and media queries ensured a consistent experience across devices, and Git and GitHub were used to track iterations as client feedback came in.

Testing & Quality Assurance

The site was tested throughout development to confirm content displayed correctly, navigation worked as expected, and the layout remained responsive across screen sizes.

Browser testing and manual review were used to catch layout issues and styling inconsistencies before the prototype was shared with the client and deployed.

Lessons Learned

Building a site for a real client taught me to think beyond code and consider the visitor's journey — what they need to see first, and how to guide them toward taking action. Planning information architecture before styling made the whole build faster and more coherent.

The project also strengthened my ability to take feedback from a non-technical stakeholder and translate it into concrete design and code changes, an essential skill for working with real clients.

Concrete outcomes: I can now plan a site's structure before writing any code, build a responsive front end that reflects a real brand, and iterate on that build based on client feedback.

Reflection

This project pushed me to think like a developer working with a real client rather than a self-directed learner. Every decision had to be justified in terms of what the visitor and the client needed, not just what looked good to me.

Looking back, this project gave me confidence that I can take an ambiguous client brief and turn it into a structured, professional website — a skill I'll keep using as I grow into a Full Stack Developer.
